## Этап 0. Зафиксировать реальную среду УКНЦ BASIC

**Цель:** прежде чем писать игру, исключить ошибки из-за несовместимого диалекта BASIC.

Задачи:

1. Запустить UKNCBTL Web.
2. Найти/подготовить образ УКНЦ с нужным BASIC.
3. Проверить минимальную программу.
4. Проверить синтаксис строковых переменных (`¤` vs фактический вводимый символ).
5. Проверить:
   - `DIM`;
   - `INKEY¤`;
   - `ASC`;
   - `RND`;
   - `SCREEN`;
   - `LINE ... BF`;
   - `PSET/PRESET`;
   - `COLOR`.
6. Написать тест, который печатает `ASC(INKEY¤)` для нужных клавиш.
7. Зафиксировать mapping клавиатуры эмулятора → коды BASIC.
8. Сделать простой benchmark графики: например 100/500/1000 filled rectangles.

**Результат:** `docs/UKNC_BASIC_NOTES.md`, содержащий только экспериментально подтверждённые факты.

**Критерий готовности:** маленькая интерактивная графическая BASIC-программа стабильно работает в Web UKNCBTL.

## Этап 1. Подготовить emulator workflow

Сразу сделать три способа проверки, чтобы разработка не оказалась привязана к одному окружению.

### 1A. Browser

- использовать `ukncbtl-wasm`;
- определить удобный формат загрузки программы: disk image либо state;
- если возможно, подготовить URL вида `...?disk0=...&run=1`;
- документировать ограничения CORS для локального hosting;
- добавить простой `python -m http.server`/аналогичный способ поднять статический сервер, если нужен.

### 1B. Linux

- собрать или установить `ukncbtl-qt`;
- описать запуск;
- проверить загрузку того же disk/state artifact;
- проверить штатную скорость эмуляции.

### 1C. Windows

- использовать release UKNCBTL или Qt build;
- описать загрузку того же образа;
- проверить клавиатуру.

**Критерий готовности:** один и тот же HELLO/graphics test запускается всеми тремя способами.

## Этап 3. Данные фигур

Задать DATA tables для I,O,T,S,Z,J,L.

Для каждого rotation state сохранить четыре клетки.

Создать debug screen/test mode, который:

1. рисует orientation;
2. по клавише переключает orientation;
3. считает/показывает overlap old/new;
4. использует differential renderer.

Особое внимание:

- T: добиться 3 совпадающих клеток на типичном quarter-turn там, где это геометрически возможно;
- I: выбрать естественные offsets;
- O: rotation не меняет экран.

**Критерий готовности:** все переходы выглядят естественно и не используют erase-all/draw-all.

## Этап 4. Differential renderer

Реализовать универсальную подпрограмму:

```
RENDER_ACTIVE_DIFF(oldState,newState)
```

Она должна сравнивать состояния в координатах стакана.

Добавить debug counters:

- erased cells;
- drawn cells.

Ожидаемые свойства:

- horizontal move на 1 для I: 1 erased + 1 drawn;
- horizontal move на 1 для компактной фигуры обычно 2–3 изменения, а не 8;
- balanced T rotation: целевой случай 1 erased + 1 drawn;
- O rotation: 0 + 0;
- ни одно обычное действие не вызывает full screen redraw.

После проверки debug UI можно отключить, код counters оставить условно доступным.

## Этап 7. Rotation kick/floor behaviour

Добавить kick tables.

Обязательные acceptance tests:

### T near wall

T у левой/правой стены поворачивается, если есть очевидное соседнее допустимое положение.

### I on floor

1. чистый ровный пол;
2. I горизонтально вплотную к полу;
3. Rotate;
4. I становится вертикальной, нижняя клетка вплотную к полу;
5. Rotate обратно;
6. I снова оказывается естественно лежащей на полу, а не остаётся поднятой.

### Anti-climb

При `ALLOW_ROTATION_CLIMB=0` многократное вращение на одном месте не должно поднимать фигуру всё выше.

## Этап 8. Gravity clock calibration

Вместо предположений провести эксперимент.

1. Сделать цикл с `INKEY¤` и счётчиком.
2. На штатной эмуляции определить приблизительное число loop iterations/sec.
3. Проверить, насколько оно меняется при движении/рендере.
4. Выбрать устойчивую модель игровых ticks.

Если простой loop-counter слишком зависит от количества отрисовки, исследовать доступные счётчики/порты/системные tick источники УКНЦ. Использовать `PEEK/INP` только после проверки документации и только если это существенно улучшает стабильность.

Сформировать таблицу gravity delay по levels.

## Этап 9. Lock delay

Ввести состояния:

```
GROUNDED
LOCK_TIMER
LOCK_RESETS
```

Правила:

- первое невозможное downward movement не lock immediately;
- move/rotate разрешён;
- успешное действие даёт grace;
- число полных reset ограничено;
- hard drop включает grounded, но оставляет окно манёвра.

Playtest на максимальном уровне: хороший игрок должен иметь реальный шанс hard-drop → rotate → shift перед lock.
